## Move and fold

| Key | Action |
|---|---|
| <kbd>↑</kbd> <kbd>↓</kbd> or <kbd>k</kbd> <kbd>j</kbd> | Move one row |
| <kbd>PgUp</kbd> <kbd>PgDn</kbd> | Move one screen |
| <kbd>Home</kbd> <kbd>End</kbd> or <kbd>g</kbd> <kbd>G</kbd> | First and last row |
| <kbd>←</kbd> <kbd>→</kbd> or <kbd>h</kbd> <kbd>l</kbd> | Fold and open a subtree. <kbd>←</kbd> on a leaf or a folded row moves to its parent |

The cursor follows its **entity**, not its line. When new data re-sorts the rows, the highlighted cgroup or process stays highlighted, and keys act on it.

## Layouts

</Figure>

<kbd>v</kbd> cycles the layouts:

- **step** (default with `--slurm`): job → step → node → task → process. Answers "how is each step doing, across nodes?".
- **node**: node → cgroup tree → process. Answers "what runs on this node?".
- **flat**: one row per process, with a NODE column and one global sort, like `top`. Where processes are off, flat lists the task cgroups instead.

On a host there is no node level, and <kbd>v</kbd> toggles between the tree and flat.

## Sort

<kbd>s</kbd> selects the next sort column (NAME, CPU%, MEM, IO-R/s, IO-W/s, PIDS, and NODE when attached); <kbd>S</kbd> reverses it. The header shows the column and the direction (`sort CPU% ▼`).

**Sort orders siblings only.** A row never leaves its parent: tree layouts sort each set of siblings at every level by the row's own value. Flat has one set of siblings, so its sort is global. Missing values (`-`) sort last in both directions; ties keep the natural order.

## Filter

<kbd>/</kbd> edits a filter; type, then <kbd>Enter</kbd> keeps it and <kbd>Esc</kbd> clears it.

- It matches a substring of the row name, a process's command name, or a cgroup's path, ignoring ASCII case. A leading `/` is ignored, so `/slurm` and `slurm` match the same rows.
- A match keeps its ancestors (opened) and its whole subtree.
- The footer shows `filter X (/ edits, Esc clears)`. With no match, the table says so.

## Detail

<kbd>Enter</kbd> opens every value of the highlighted row: the full path or the pid, command name and full command line, then each metric the node announced, raw and formatted. It also shows metrics that have no column, such as the pressure stall times and page faults, and metrics of future sources. `NA` means the value was not announced or the file is absent. On a job, step or folded row, the values are the sums. Any key closes it.

## Help and log

<kbd>?</kbd> shows the keys of the current mode, a legend of the INT, W and PIDS columns, a table with each agent's CPU, memory, output, drops, errors and clock skew, and the newest log lines (srun messages, warnings from agents, recording events). Any key closes it.

## Pause, theme, quit

| Key | Action |
|---|---|
| <kbd>z</kbd> | Pause: hold new data so the screen stays still; <kbd>z</kbd> again applies it. The clock stops too, so no node turns stale. A pause ends by itself after 4096 held batches |
| <kbd>t</kbd> | Next [theme](/unjam/guide/themes/) |
| <kbd>q</kbd> or <kbd>Ctrl</kbd>+<kbd>C</kbd> | Quit |

All keys: [Keys reference](/unjam/reference/keys/).
