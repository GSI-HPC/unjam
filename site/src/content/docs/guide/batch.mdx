---
title: Scripts and batch mode
description: Use unjam --batch for text snapshots in scripts, over ssh and in cron, and --rule to choose what they contain.
---

`--batch N` prints N text snapshots, one per interval, instead of starting the TUI, then exits. It works in every mode: on a host, with `--slurm` and with `--replay`.

```sh
unjam --batch 1
unjam --slurm=4242 --batch 3 --rule '* . 1s c'
unjam --replay rec/*.arrows --at end --batch 1
ssh node17 unjam --batch 2 --root /sys/fs/cgroup/system.slice
```

Without `--batch`, a stdout that is not a terminal stops unjam with `stdout is not a terminal; use --batch N (or ssh -t)`.

- The snapshot shows the same rows and sort as the TUI, in the default layout of the mode.
- The footer line counts nodes, stale nodes, decode errors, dropped ticks, and `missing`: nodes that never reported.
- The first snapshot waits until every node has sent a rate: at most 3 s plus two intervals.
- Control characters in names (ESC and others) are printed as `?`, so a crafted process name cannot drive your terminal.
- Piping into `head` is fine: unjam exits 0 when the pipe closes.

## Choose the content with rules

`--rule` replaces the default sampling rules (see [Control the sampling](/unjam/guide/sampling/)). That is how a script asks for exactly the subtree it needs:

```sh
# Node 0's step_0 with processes every 500 ms, nodes 1-2 cgroups only every 2 s.
# Nothing else matches, so the rest is off.
unjam --slurm=$J --batch 3 --rule '0 step_0 500ms p' --rule '1-2 . 2s c'
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Normal exit |
| 1 | An error, for example srun failed, the job is not running, or a recording failed |
| 2 | Usage error, or `--slurm` without a value matched no single running job (the jobs are listed) |
| app's | `unjam record` exits with the application's exit code, or 128 + signal |
